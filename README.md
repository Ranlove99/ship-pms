# 船舶 PMS · 计划维护与合规记录系统

面向**单船、离线、散货/杂货船**的计划维护系统，打包为飞牛 fnOS 可安装的 `.fpk`。

不连接云端、不依赖外网、不需要 Docker。一个进程、一个 SQLite 文件、一个 Unix socket，NAS 断网也能全功能使用。

**开发者**：Ranlove99

## 2. 安装

### 前置

- 飞牛 fnOS（建议 ≥ 1.1.3100，统一网关需要）
- 应用中心已安装 **python312** 运行时（本应用声明了 `install_dep_apps=python312`，通常会提示自动安装）
- 可用存储空间 ≥ 100 MB（应用本体 668 KB，数据随记录增长）

### 步骤

1. 下载 `ship-pms_1.0.0.fpk`
2. 飞牛 **应用中心 → 手动安装** → 选择该文件
3. 按向导填写：船名（必填）、IMO（7 位数字，可留空）、船旗、船级社、总吨、船时区；管理员账号与口令
4. 安装完成后，桌面出现「船舶PMS」图标，点击进入

> 向导中的管理员口令留空时，安装程序会随机生成并写入应用日志
> `/var/apps/ship-pms/var/app.log`，搜索「已生成管理员口令」。

### 首次登录

- **从应用中心图标进入**：飞牛统一网关已校验 NAS 登录态，系统自动识别账号，无需再次登录。
  首次进入的 NAS 用户默认为「普通船员」角色，需由管理员在「设置 → 账号」中调整角色。
- **本地直连**：访问 `http://<NAS地址>:端口/` 需要账号口令（安装向导中设置的那个）。
  直连接口默认不对外暴露，仅用于排障。

### 角色

| 角色 | 可做 |
|---|---|
| 系统管理员 | 全部，含账号与备份 |
| 船长 | 核签电子记录簿、验收工单、查看全船、维护证书 |
| 轮机长 | 建计划、派工、验收、提交记录簿、库存与证书 |
| 轮机员/驾驶员 | 执行工单、报缺陷、领料、更新运行小时 |
| 普通船员 | 查看、报缺陷 |

## 3. 五分钟走一遍

1. **设置 → 船舶资料**：补全船名、IMO、船旗、船级社（会出现在检查包封面）
2. **维护计划**：检查预置的 43 条计划，把周期改成实船手册的值；不适用的停用
3. **设备树**：核对你船的实际设备，删掉没有的、补上缺的
4. **到期清单**：勾选几条 → 批量派工
5. **工单**：打开一条 → 开始 → 逐项打勾 → 提交完成 → 验收（会顺延计划）
6. **电子记录簿**：新增一条燃油加装 → 提交 → 用船长账号核签
7. **报表**：生成 PSC 检查包 → 浏览器打印为 PDF

### 批量改预置模板（推荐做法）

预置的 43 条计划、64 个设备逐个点太慢。用 CSV 批量改：

1. **设置 → 批量维护 → 导出**（选「维护计划」），得到一份带现有数据的 CSV
2. Excel 打开（若提示编码，选 UTF-8），改周期、检查项、预计工时等
3. **导入 → 检查文件**：先预检，看到「更新 N / 新增 N / 跳过 N / 错误 N」和逐行变更对比
4. 确认无误后点「确认导入」

规则：

- 按编码匹配：计划用「计划编码」、设备用「设备编码」、备件用「备件编码」、证书用「证书名称」
- 只更新文件里出现的列，其余保持原值
- **不会自动重算到期日**：改了周期还需要调整下次到期时，请在文件里填「下次到期」列
- 预检会逐行报错（数字格式、编码不存在、枚举值非法等），错误行不会写入
- 全部导入操作记入审计日志（`import.plans` 等）

同样的方式可以批量维护设备、备件、证书。设备表里「上级编码」留空表示顶层系统。

## 4. 数据、备份与恢复

### 路径（安装后）

| 内容 | 路径 |
|---|---|
| 程序 | `/var/apps/ship-pms/target/`（符号链接到所选存储卷） |
| 数据库 | `/var/apps/ship-pms/var/data/pms.db` |
| 日志 | `/var/apps/ship-pms/var/app.log` |
| 附件 | `/var/apps/ship-pms/var/attachments/` |
| 备份 | 共享目录 `ship-pms/export/backup/`（文件管理器中可见） |

### 备份

- 自动：每日首次写入时检查并生成快照（也可在「设置 → 备份 → 立即备份」手动触发）
- 保留份数在「设置 → 提醒阈值 → 备份保留份数」配置，默认 30 份，超出删除最旧
- 备份是完整数据库快照，用飞牛文件管理器直接拷到外部硬盘即可带走

### 恢复

1. 停止应用（应用中心 → 停用）
2. 把备份文件改名为 `pms.db`，覆盖 `/var/apps/ship-pms/var/data/pms.db`（先备份现有文件）
3. 启动应用
4. 进入「设置 → 完整性校验」确认数据库与哈希链完整

> 升级前系统会自动备份到 `var/backups/pre-upgrade-<时间>.db`；
> 卸载前会把快照写入共享目录 `uninstall-backup/`。

### 校验

「设置 → 完整性校验」会做三件事：SQLite 完整性检查、审计日志链重算、各记录簿哈希链重算。
断链会指出具体条目序号。这个结论也会出现在 PSC 检查包的第 8 节。

## 5. 合规边界（请务必读）

- 本系统**提供**符合 IMO 电子记录簿导则（MEPC.312(74)、MEPC.372(80)）的记录机制：
  追加式条目、UTC 时间戳、更正留痕、轮机长提交 + 船长核签、逐条哈希链接。
- **正式以电子记录簿替代纸质记录，须经船旗国主管机关或其授权认可组织批准并签发声明**，
  声明副本应留船。装了这个系统不等于已经取得该批准。
- 预置的设备树、维护周期、证书清单是**行业通行骨架**，不能替代厂家手册、船级社规范与公司 SMS。
  装船后必须由轮机长逐条核对修订。
- 系统生成的所有报表均来自系统内记录，不做人工修饰。记录造假的责任在使用者。

## 6. 排错

| 现象 | 原因与处理 |
|---|---|
| 应用中心提示「不是有效的 fpk 文件」 | 包不完整。重新下载；或 `tar tzf ship-pms_1.0.0.fpk` 检查是否有 `app.tgz`、`cmd/`、`manifest` |
| 安装后图标点开空白 | 服务未启动。应用中心 → 停用 → 启用；仍不行看 `var/app.log` |
| 安装失败提示找不到 python3 | 先装 python312 运行时，再装本应用 |
| 安装失败提示「数据目录不可写」 | 1.0.0 的安装脚本在解压前就建了 `@appdata/ship-pms`，属主变成 root。升级到 1.0.1 即可；若仍有残留：`sudo rm -rf /vol1/@appdata/ship-pms` 后重装 |
| 页面 404 / 样式丢失 | 网关前缀问题。确认访问地址形如 `/app/ship-pms/`，检查 `app/ui/config` 的 `gatewayPrefix` |
| 状态显示「异常」而不是「已停止」 | 生命周期脚本 status 退出码问题，通常伴随进程异常退出，看日志 |
| 时间不对 | 修改「设置 → 船舶资料 → 时区」。存储始终为 UTC，显示按船时换算 |
| 记录簿显示「链异常」 | 数据库被外部修改过。立即做完整性校验，导出当前数据，联系维护方 |
| 备份失败 | 共享目录不可写。检查 `config/resource` 的 data-share 是否创建成功 |

日志位置：`/var/apps/ship-pms/var/app.log`（启动、种子数据、错误都会记在这里）。

## 7. 开发与构建

### 目录

```
ship-pms/
├── src/                  应用源码（纯 Python + 原生前端）
│   ├── wsgi.py           入口（waitress + Unix socket）
│   ├── app.py            装配：蓝图、中间件、错误处理
│   ├── config.py         路径与环境变量
│   ├── db/               连接、迁移、种子数据
│   ├── routes/           仅做参数校验与响应组装
│   ├── services/         全部业务逻辑
│   ├── middleware/       前缀剥离、认证鉴权
│   ├── static/           CSS 与前端脚本（无构建步骤）
│   └── templates/        Jinja2 页面
├── packaging/            fpk 骨架：manifest、cmd、config、wizard、app/ui、图标
├── build/                构建产物（每次重建，勿手改）
├── scripts/
│   ├── build_fpk.sh      构建 + 结构/校验和/二进制扫描
│   ├── make_icons.py     生成 ICON.PNG / ICON_256.PNG
│   └── selfcheck.py      21 项单元测试
└── docs/                 验收清单与截图
```

### 构建

```bash
python3 scripts/make_icons.py            # 重新生成图标（可选）
bash scripts/build_fpk.sh 1.0.1          # 产物 build/ship-pms_1.0.1.fpk
```

构建脚本每次从 `packaging/` 重建打包目录（manifest、cmd、config、wizard、ui、图标），
再把 `src/` 与 `vendor/` 放进 `app/`。`build/` 下所有内容都是可再生产物，不要手改。

脚本会：清理字节码 → 装配骨架 → 安装纯 Python 依赖 → 删除所有 `.so`
→ 扫描 ELF（非零即失败）→ 导入自检 → `fnpack build` → 校验七要素结构与 `app.tgz` MD5
→ 检查 `install_init` 是否误碰数据目录（防止重犯 1.0.0 的安装失败）。

`fnpack` 默认从 `static2.fnnas.com` 下载 1.2.3；离线环境可 `FNPACK=/path/to/fnpack` 指定。

### 测试

```bash
python3 scripts/selfcheck.py             # 40 项：到期计算、迁移幂等、状态机、库存守恒、单据过账规则、哈希链篡改检测
```

### 技术选型与约束

- **纯 Python 栈**：Flask + waitress + SQLite，无 C 扩展，无 Node 构建
- 包内零二进制 → `platform=all`，x86 与 ARM 的 NAS 装同一个包
- 前端无框架、无 CDN，离线可用
- 单进程多线程，SQLite WAL；单船并发（<20 人）足够
- 若需改造成船队系统，需要另行设计同步与冲突合并，不在本版本范围
